# Kira — Wikipedia Chat + Continuous Learning (Flat Root Edition)

Every file in this release is directly in the repository root, with **no subdirectories**. `index.html` is the Kira application itself (not a redirect).

## Deploy to GitHub Pages

1. Extract the ZIP.
2. Upload **all extracted files** directly into the root of your GitHub repository — not inside another folder.
3. In GitHub **Settings → Pages**, choose **Deploy from a branch**, select your main branch and **/(root)**, then save.
4. Visit the published HTTPS site. The app requires a live Internet connection to fetch new Wikipedia articles.

There is **no backend**, API key, build process, or installation needed to deploy. GitHub Pages provides the HTTPS origin required for Web Workers and IndexedDB. Opening `index.html` directly from a `file://` URL will not work reliably.

## Local development

From the directory containing `index.html`, run:

```sh
python -m http.server 8000
```

Open `http://localhost:8000/`.

## Fixed: garbled chatbot output

Kira's randomly initialized ~28K-parameter byte-level Transformer could produce invalid UTF-8 and random-looking text. This was not a Wikipedia download failure: training on a few articles does not turn such a small network into a capable language model.

**The default response mode is now Wikipedia-grounded.** A dedicated browser Web Worker finds Wikipedia articles, retrieves their plain-text introductory extracts, and shows clear source links. This produces readable, source-backed factual answers **without requiring an LLM API or model checkpoint**. The chat worker can also return greetings and use a locally cached Wikipedia article when the network is unavailable. If nothing relevant can be retrieved, it reports that limitation instead of inventing an answer.

In Settings → Answer mode, users can explicitly switch to **Experimental neural generation** to inspect the actual tiny Transformer. It may be incoherent because the model is not pretrained and its context is very short. When it generates invalid UTF-8, the app reports that instead of displaying replacement characters. Wikipedia-grounded answers are **retrieval**, not output generated by the trained Transformer; neural training independently continues and is saved as before.

To update an existing deployed Kira website, replace **every root file** with this release. Keep the same GitHub Pages domain and browser site data if you want to preserve IndexedDB articles, checkpoints and local conversations. You do not need to reset the model.

## Features

- Readable Wikipedia-grounded chat by default with source links, follow-up topic handling, and offline saved-article fallback
- Explicit experimental neural completion mode; never passes invalid UTF-8 off as reliable chat
- Autonomous Wikipedia article discovery, downloading and topic diversification
- Local article and training-example persistence in IndexedDB
- Byte-level BPE tokenizer fitted to discovered articles
- Genuine tiny causal Transformer with softmax cross-entropy, backpropagation, AdamW and gradient accumulation
- Train/validation splits, replay sampling, evaluations, learning-rate adjustment and checkpoint history
- CPU JavaScript worker training, isolated inference worker, chat-priority scheduling
- Start/Pause/Resume/Stop controls, usage limits, activity feed and training metrics
- Saved model weights and optimizer state restored across sessions

The model is extremely small and starts with random parameters; generating fluent factual answers comparable to a pretrained LLM is not feasible from scratch on an ordinary phone. **WebGPU is not implemented** in this version; training runs on the JavaScript CPU worker. Browser resource limits and Wikimedia API availability may affect continuous operation. Nothing executes after closing the page; saved enabled settings let training resume after reopening it.

## Runtime file map (all files at root)

- `index.html`: original Kira UI and live Training Lab
- `app.js`, `lab.js`, `api.js`, `messages.js`, `conversations.js`, `context.js`, `settings.js`, `ui.js`, `chart.js`, `markdown.js`: app frontend
- `styles.css`, `base.css`, `layout.css`, `chat.css`, `panels.css`, `responsive.css`: original interface CSS
- `controller.js`: worker orchestration, resource controls, chat API
- `discovery-worker.js`: Wikipedia discovery and article dataset collection
- `training-worker.js`: genuine continuous Transformer training
- `inference-worker.js`: Wikipedia-grounded chat, separate local experimental neural generation
- `wiki-answer.js`: Wikipedia search/extract logic, topic queries, source formatting, cached fallback
- `db.js`: IndexedDB persistence
- `bpe.js`: byte-pair tokenizer
- `transformer.js`: model forward/backward/optimizer implementation
- `test-run.mjs`, `test-wiki.mjs`: optional self-contained Node verification
- `marked.js`, `purify.js`, `highlight.js`, `language-*.js`, `fontawesome.svg`: vendored offline browser presentation dependencies
- `*-LICENSE`, `THIRD_PARTY_NOTICES.md`, `LICENSE`: bundled notices

This release omits the **unused legacy Python backend and Node server** from the original repository, because they are not loaded by the browser edition. All runtime application files are present at root.

## Tests

Node 20+ is only needed for the optional neural engine test:

```sh
node test-run.mjs
node test-wiki.mjs
```

The tests check tokenizer round trips, real gradient updates, decreasing training loss, checkpoint restoration, sampled inference, grounded Wikipedia response formatting, offline fallback, follow-ups, and cross-origin API parameters. They use mocked Wikipedia responses and do not confirm browser IndexedDB, live Wikipedia connectivity or page-reload behavior.
